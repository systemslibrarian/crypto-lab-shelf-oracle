8. Shelf Oracle

crypto-lab-shelf-oracle · PRIVACY · completes Patron Shield → Oblivious Shelf → Shelf Oracle

Thesis. Two-server PIR buys information-theoretic privacy by assuming non-collusion. Single-server computational PIR removes that assumption — and this is what removing it costs. (Not "deployed PIR has one server": two-server architectures are active and practical, and the lab is about the trade, not about one side being obsolete.)

Construction. Computational single-server PIR, RLWE-based, SealPIR-style (Angel et al., IEEE S&P 2018). The baseline client encrypts a direct selection vector under BFV; the server computes the inner product homomorphically; one ciphertext returns. A separate act covers the same 64 records with four fixed ciphertext blocks: one client-prescaled monomial block and three encrypted-zero blocks expand to 64 selectors through real Galois substitution and key switching. All four queries are sent, all 64 records are scanned and all four responses return. No plaintext block or index field is sent; the choice is present only under encryption and hidden under the stated assumptions. Reusable evaluation-key bytes, operation counts and noise stay visible. Multi-dimensional indexing remains out of scope; query compression must not be described as sublinear server work.

Stateful construction. A separate bounded lesson adapts the current major revision of Zhou–Park–Shi–Zheng, Piano (ePrint 2023/452, revision 12 November 2023; IEEE S&P 2024). Fix `N = 64`, `B = 512`, eight chunks of eight, `Q = floor(sqrt(N) ln N) = 33`, 256 primary hints and eight punctured backups/replacements per chunk. Client-specific setup streams the static database and retains secret PRF-defined parity state; server `ProcessDB` is identity/none. Each online request is exactly eight bytes, one in-range index per chunk; the server probes and XORs eight records and returns exactly 512 bytes. The eight-byte upload is this fixed teaching codec, not the reference implementation's protobuf transport of `uint64` indices and not a copied Piano benchmark. Recover with `DB[x] = P xor response xor DB[r]`, then refresh with the consumed punctured backup. Do not resample when `r = x` or when replacements repeat: both are valid. When `r = x`, the target value may appear on the wire; privacy is distributional, not an absence rule. A cached application repeat must spend a normal, previously unused effective target as cover. Commit any allocated target and refresh slot before send; a missing or malformed response never rolls them back for retry.

Stateful limits. The live path takes private entropy only from WebCrypto; deterministic injection is test-only. Under the independent-coordinate model, the exact setup fixed-target miss is `(7/8)^256`; the session primary-hint availability union bound is `33 * (7/8)^249 ~= 2^-42.92`, because as many as seven programmed hints in a chunk may be deterministic non-hits. Label this only as a primary-hint availability bound under independent secret coordinates and the bounded refresh schedule—not 128-bit or end-to-end security. Each chunk has eight one-use effective targets and exactly eight refresh slots, so the canonical fixed model never needs a ninth slot; `HINT_UNAVAILABLE` is a defensive invariant guard, not a learner exhaustion exercise. Cached application repeats choose distinct unused effective targets for cover, and the separate 33-commit window is the normal epoch ceiling. Corrigan-Gibbs–Henzinger–Kogan (ePrint 2022/081) says its most efficient scheme is optimal for its trade-off between server online time and client storage; this bounded adapter does not numerically instantiate or transfer that model-specific theorem. This is a static, honest-but-curious, client-preprocessing teaching adaptation. It does not inherit Piano's asymptotic theorem, reference benchmarks, pipelining or dynamic construction, and it is not the Lin–Mook–Wichs Ring-LWE doubly-efficient scheme.

Noise exhaustion. Push the database size until the budget runs out and decryption returns garbage. NOISE_BUDGET_EXHAUSTED.

Negative claim (NEG-1). PIR hides the selected index under its security model. It does not inherently hide query occurrence, timing, frequency, database size, or other traffic metadata. Padding and traffic shaping are separate mechanisms — note that these responses are fixed-size by construction, so response length is one thing the selected protocol covers, and say which properties come from the protocol versus from the deployment. Link forward to Search Vault's leakage-abuse attacks and ORAM Vault's access-pattern hiding.

Negative claim (NEG-2). Stateful preprocessing PIR is not ORAM. This adaptation's server sees one physical probe in each fixed chunk and privacy rests on their secret PRF-defined distribution plus state discipline. ORAM hides a logical access sequence from a server observing data-dependent physical accesses. Do not describe either primitive as supplying the other's guarantee.

Negative claim (NEG-3). A database digest, record-embedded hash and external state high-water mark are not answer integrity or freshness. An old database with its old valid record tags can still verify. The high-water mark detects rollback only when retained outside the state it protects. A deployment needs authenticated, monotonic database versioning; this lesson has none.

BFV failure codes. NOISE_BUDGET_EXHAUSTED · DIM_MISMATCH · PARAM_UNSAFE · INDEX_OUT_OF_RANGE

Stateful failure states. WINDOW_EXHAUSTED · STATE_LOST · DATABASE_UPDATED · ROLLBACK_DETECTED · MALFORMED_RESPONSE · REQUEST_ABANDONED. HINT_UNAVAILABLE · NO_COVER_TARGET · STATE_INVALID are defensive invariant guards, not naturally exhausted paths in the canonical fixed model. A local preflight failure still sends a fixed-shape dummy and receives 512 bytes; it does not recover a record. State loss and every database update require full client preprocessing. Demonstrate the update cost and stale-result failure, then rebuild and independently recover the changed record.
